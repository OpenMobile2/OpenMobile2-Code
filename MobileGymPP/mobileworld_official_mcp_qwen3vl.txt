MobileWorld official MCP eval: prompt + runtime
================================================
Default command (README):

  mw eval --agent_type qwen3vl --enable_mcp ...

Sources:
  src/mobile_world/agents/utils/prompts/qwen3vl.py
      MOBILE_QWEN3VL_PROMPT_WITH_ASK_USER
      MOBILE_QWEN3VL_USER_TEMPLATE
  src/mobile_world/agents/implementations/qwen3vl.py
      Qwen3VLAgentMCP.predict
  src/mobile_world/runtime/client.py
      AndroidMCPEnvClient.reset_tools / execute_action
  src/mobile_world/core/runner.py
      env.reset_tools then create_agent then loop predict/execute


1. Runtime shape (not a session)
--------------------------------
NOT qwen35_session. Every model call is a fresh 2-message request:

  [system]  full prompt, including this task's MCP schemas
  [user]    instruction + flattened history text + CURRENT screenshot

There is no role=assistant history, no role=tool, no last_n image collapse
inside the API messages. History is flattened into the user text field
"Task progress: Step 1: ...; Step 2: ...".

Every step re-sends the same system (MCP defs included). Tools do not
change after open_app.


2. How tools are attached (task-level, frozen)
----------------------------------------------
Env starts AndroidMCPEnvClient, list_tools_sync() from cloud MCP servers:
  DashScope SSE:  amap, stockstar
  ModelScope HTTP: gitHub, jina, arXiv

Before the agent is created, runner calls:

  env.reset_tools(task_type=task_name)

  - no tag agent-mcp  -> tools = []
  - has agent-mcp     -> keep tools whose name contains the MCP-* app
                         suffix (Amap / Github / jina / arXiv / stockstar)

agent.tools = env.tools for the whole episode.

MCP is not bound to a phone app. Model can call amap_maps_distance from
the home screen. Opening Chrome/Messages does not change <tools>.


3. System prompt (MCP task: tools non-empty)
--------------------------------------------
Jinja inserts extra lines after mobile_use:

  tools="\n".join(json.dumps(t, ensure_ascii=False) for t in self.tools)

Those dumps are MCP SDK model_dump (name / description / inputSchema),
NOT OpenAI {"type":"function","function":...}.

Full text:

</tools>

For each function call, return a json object with function name and arguments within <tool_call></tool_call> XML tags:
<tool_call>
{"name": <function-name>, "arguments": <args-json-object>}
</tool_call>

# Response format

Response format for every step:
1) Thought: one concise sentence explaining the next move (no multi-step reasoning).
2) Action: a short imperative describing what to do.
3) A single <tool_call>...</tool_call> block containing only the JSON: {"name": <function-name>, "arguments": <args-json-object>}.

Rules:
- Output exactly in the order: Thought, Action, <tool_call>.
- Be brief: one sentence for Thought, one for Action.
- Do not output anything else outside those three parts.
- If finishing, use mobile_use with action=terminate in the tool call.


4. User prompt (every step) + image
-----------------------------------
Text:

The user query: {instruction}
Task progress (You have done the following operation on the current device): {steps}

Plus a separate image_url part = current screenshot. ALWAYS present,
including after MCP.

Step 0: {steps} is empty.
After GUI: append "Step k: {Action sentence}; "
After MCP: append onto the previous step:
  ; Tool call result: <tool_response>{json}</tool_response>


5. Model output
---------------
Thought: ...
Action: ...
<tool_call>
{"name": "mobile_use", "arguments": {"action": "click", "coordinate": [x, y]}}
</tool_call>

or

<tool_call>
{"name": "amap_maps_distance", "arguments": {"origins": "...", "destination": "..."}}
</tool_call>

name != mobile_use  -> JSONAction(action_type=mcp, action_name=name, action_json=args)


6. Env execute
--------------
GUI: Android click/type/... then screenshot.
MCP: remote call_tool_sync, then get_screenshot. Observation has both
     screenshot and tool_call JSON. qwen3vl sends BOTH to the model
     (JSON in Task progress text, screenshot as image_url).


7. Example (CheckDistanceMcpTask)
---------------------------------
instruction:
  帮我用高德mcp查一下从杭州东站到它的直线距离？只需要回答数字。
apps: MCP-Amap, Chrome
system <tools> = mobile_use + all amap_* tools, frozen for the episode.

step 0:
  user text: query + empty progress
  user image: home screenshot

assistant:
  Thought: ...
  Action: query Amap distance
  <tool_call>{"name":"amap_maps_distance","arguments":{...}}</tool_call>

step 1:
  user text: same query + "Step 1: query Amap distance; Tool call result: <tool_response>...</tool_response>;"
  user image: screenshot after the call (phone UI usually unchanged)
  NO role=tool message.


8. Not this (mai_ui_agent, not the README default)
--------------------------------------------------
MAI uses a multi-turn session: system once-per-call with "## MCP Tools",
true assistant history, and if tool_call is set it sends JSON text ONLY
(no image). That is a different agent. Official documented eval is qwen3vl.
